# R2 汇率历史库设计

## 背景与目标

当前 `exchange_rates` 表只保留每种币种的最新值。用户打开页面后，服务仍可能重复访问最新汇率接口；美股收益计算还会按起止日期分别读取 USD/CNY 历史汇率。上游暂时不可用时，长期区间的股票收益预热容易失败。

本次改造需要实现：

- 首次同步当前支持的 9 种外币过去 10 年历史汇率，并保存为一个 R2 JSON 文件。
- 服务启动时在后台补齐 R2 文件，再把文件中 D1 尚不存在的记录写入数据库。
- 北京时间每天 00:00 读取最新可用汇率，同时更新 R2 文件、D1 历史表和现有最新汇率表。
- 美股历史收益优先读取 D1 历史汇率，数据库缺失时才访问外部接口。
- 历史文件和数据库只保留滚动 10 年数据。
- 同步过程输出便于本地和线上排查的结构化日志。

## 支持币种与汇率口径

历史库覆盖 USD、HKD、EUR、JPY、GBP、SGD、AUD、CAD、CHF。

文件与数据库统一保存「1 单位外币折合多少人民币」，字段名为 `cnyRate` 或 `cny_rate`。Frankfurter 使用 CNY 为基准返回「1 人民币可兑换多少外币」，写入前必须取倒数。CNY 本身不写入历史表，读取最新汇率时仍在响应中补充 `CNY: 1`。

汇率日期使用上游数据日期，不把周末或节假日伪造成交易日。查询某个行情日期时，返回不晚于该日期的最近一条汇率。

## R2 文件

启用 R2 绑定 `RATES`，对象键固定为 `exchange-rates/history.json`。文件采用以下版本化结构：

```json
{
  "version": 1,
  "base": "CNY",
  "checkedThrough": "2026-08-02",
  "updatedAt": "2026-08-03T00:00:12+08:00",
  "dates": {
    "2026-07-31": {
      "source": "Frankfurter 央行参考汇率",
      "rates": {
        "USD": 7.18,
        "HKD": 0.92,
        "EUR": 8.31,
        "JPY": 0.048,
        "GBP": 9.61,
        "SGD": 5.58,
        "AUD": 4.69,
        "CAD": 5.23,
        "CHF": 8.92
      }
    }
  }
}
```

`checkedThrough` 表示已向上游检查到的 UTC 日期，不代表该日一定有汇率。北京时间午夜执行时仍处于前一个 UTC 日期，因此任务会补齐刚结束且已经发布数据的 UTC 工作日，避免跳过尚未发布的汇率。

首次不存在文件时，从截止日期向前推 10 年，按最多 1 个自然年一个窗口分段请求 Frankfurter。所有分段成功并通过校验后才合并写入 R2，不保存半成品。文件已存在时，从 `checkedThrough` 的下一天补到当前 UTC 日期；同时删除滚动窗口以前的数据。

R2 写入使用对象 ETag 条件。若其他 Worker 已更新对象，本次重新读取、合并并重试，避免并发启动或 Cron 覆盖较新的文件。

## D1 数据模型

新增 `exchange_rate_history` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 自增主键 |
| `currency` | text | 外币代码 |
| `cny_rate` | real | 1 单位外币折合人民币 |
| `rate_date` | text | 上游汇率日期，格式为 `YYYY-MM-DD` |
| `source` | text | 数据来源 |
| `fetched_at` | text | 本地取得记录的时间 |

建立 `(currency, rate_date)` 唯一索引和 `(currency, rate_date DESC)` 查询索引。R2 文件导入 D1 时使用 `INSERT OR IGNORE`，已有键严格不更新。首次约 2 万条记录按不超过 100 条语句一批写入，不能构造单个超大 D1 batch。同步成功后删除 10 年滚动窗口以前的历史记录。

保留现有 `exchange_rates` 表。每次导入后，从历史表为每个币种选择最新记录并 upsert 到该表，使页面、资产快照和现有接口无需改变汇率口径。

## 同步服务

新增独立汇率历史服务，职责如下：

1. 读取并严格校验 R2 文件的版本、基准币种、日期和数值。
2. 文件不存在时分段回填 10 年历史；文件存在时补齐尾部日期。
3. 合并结果、裁剪 10 年以前数据，并通过条件写入保存 R2 文件。
4. 使用 `INSERT OR IGNORE` 将文件全部记录导入 D1。
5. 裁剪 D1 过期记录并刷新 `exchange_rates` 最新值。
6. 返回文件日期数、D1 新增数、最新汇率日期和失败信息。

若文件已覆盖当前截止日期，启动同步不访问上游，只执行幂等 D1 导入。这保证数据库被删除或更换后仍能由 R2 文件恢复。

最新汇率 API 改为优先读取 D1 中每个币种的最新值。数据库无完整数据时执行同步。用户手动刷新时即使文件已检查到当前截止日期，也强制请求一次最新汇率接口、合并合法的新数据，并继续记录当前用户的资产快照。

## 美股历史汇率读取

行情计算器通过注入的历史汇率读取器查询 D1：

```text
SELECT ... FROM exchange_rate_history
WHERE currency = 'USD' AND rate_date <= ?
ORDER BY rate_date DESC
LIMIT 1
```

D1 命中时不访问 Frankfurter。D1 缺失时保留现有 7 天窗口外部查询作为兜底；外部查询成功后将该条记录补入 D1，但不直接改写 R2。下一次完整同步会把上游尾部数据纳入 R2。超过滚动 10 年的行情按历史库最早边界处理，不扩大文件保留期。

## Worker 启动与 Cron 分流

Worker 配置两条 UTC Cron：

- `0 16 * * *`：北京时间每天 00:00，同步汇率历史。
- `10 20 * * *`：北京时间每天 04:10，预热市场收益。

`scheduled` 必须根据触发器的 Cron 表达式分流，不能让两个任务在两个时间都执行。

每个新 Worker 实例首次收到请求时通过 `ctx.waitUntil` 启动后台流水线：先完成汇率历史同步，再运行市场收益预热。普通请求不等待该流水线。若汇率同步失败，记录错误后仍允许市场预热使用 D1 既有汇率和外部兜底。

## 错误处理与日志

- R2 文件解析失败、版本不支持或数据非法时，不覆盖原对象，也不导入可疑数据。
- 首次回填或增量补齐的任一请求失败时，不写半成品文件。
- R2 成功写入而 D1 导入失败时保留文件；下次启动重新导入。
- 周末和节假日允许上游返回空区间，但仍推进 `checkedThrough`。
- 外部接口设置超时和有限重试；多个年度窗口采用有限并发。
- 日志统一使用 `[exchange-rate-history]` 前缀，事件包括 `file_missing`、`file_loaded`、`backfill_start`、`backfill_complete`、`r2_write`、`d1_import`、`latest_refresh`、`sync_complete` 和 `sync_failed`。
- 日志记录区间、记录数、耗时、重试次数和错误原因，不记录用户 ID、Cookie 或上游响应正文。

## 测试策略

采用测试驱动开发，至少覆盖以下行为：

- 首次无文件时按年度窗口回填完整 10 年，并只在全部成功后写一个 JSON 对象。
- 9 种汇率全部转换为「1 单位外币折合人民币」。
- 已有文件只补 `checkedThrough` 之后的数据。
- 周末空数据推进检查日期，但下一工作日仍能正确补入。
- ETag 冲突会重新读取、合并和重试，不覆盖较新对象。
- 文件损坏或版本不兼容时拒绝覆盖和导入。
- 文件导入 D1 使用 `INSERT OR IGNORE`，重复启动新增数为 0。
- 同步后同时裁剪 R2 和 D1 的 10 年以前数据。
- `exchange_rates` 始终反映每个币种最新历史记录。
- 最新汇率 API 优先读取 D1，缺失或手动刷新时调用同步。
- 美股历史汇率优先命中 D1；缺失时外部查询并补入 D1。
- 启动任务先同步汇率再预热市场收益，且不阻塞请求。
- UTC `0 16 * * *` 与 `10 20 * * *` 正确分流到两个任务。
- 结构化日志覆盖成功、空更新、并发重试和失败路径。

## 验收标准

- R2 中存在一个合法的 `exchange-rates/history.json`，覆盖当前支持的 9 种外币最近 10 年可用汇率。
- 服务启动时先补齐文件，再将 D1 缺失记录写入数据库；已有记录不更新。
- 北京时间每天 00:00 自动检查并保存最新汇率。
- 页面读取最新汇率不再在每次 Worker 冷启动后必然访问外部接口。
- 美股收益计算在 D1 有对应历史汇率时不访问汇率上游。
- 历史文件和 D1 不保留滚动窗口以前的数据。
- 单个同步失败不会破坏已有 R2 文件或 D1 数据。
