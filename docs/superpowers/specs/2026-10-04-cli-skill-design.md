# 资产星图 CLI 与 AI Skill 设计

日期：2026-10-04

## 已确认的需求

- 给 AI 提供资产系统的查询和写入能力。
- 使用 CLI 与 Skill，不增加 MCP。
- CLI 只能通过 HTTP 接口访问后端，不能直接访问 SQLite。

以下是待确认的第一版设计，不代表已经实现。

## 架构

新增 Go 命令入口 `go-backend/cmd/fulibu`。CLI 使用独立 HTTP 客户端调用现有后端；浏览器和 CLI 共用后端业务服务。数据库驱动、SQL 和数据库路径不得进入 CLI 的依赖链。

Skill 保存在项目 `skills/fulibu/SKILL.md`，描述触发场景、命令选择、参数单位及错误处理。提供本机安装步骤，但不自动修改其他 AI 客户端配置。

第一版不提供交易流水、实际交易执行或任意 SQL 功能。

## 接口与命令

| CLI 命令 | HTTP 接口 | 第一版行为 |
|---|---|---|
| `portfolio summary` | 新增 `GET /api/portfolio/summary` | 后端汇总总额、类别和币种占比，返回估值与汇率日期；不更新资产或历史 |
| `assets list` | `GET /api/assets` | 支持名称、代码、类别过滤 |
| `assets get --id` | `GET /api/assets?id=…`，补充单项查询 | 查询当前用户的指定资产 |
| `assets create` | `POST /api/assets` | 新增资产；股票和基金必须提供代码及数量 |
| `assets update --id` | `PATCH /api/assets` | 扩展名称、备注和按字段修改；未传入字段保持原值 |
| `assets archive --id` | 新增归档接口 | 标记归档，保留原记录；后续当前资产汇总排除归档记录 |
| `history list` | `GET /api/history` | 增加日期范围筛选，保留现有条数限制 |
| `market get` | `GET /api/market` | 返回行情、区间表现、日期、来源与过期状态 |
| `rates get` | `GET /api/exchange-rates` | 查询汇率，说明现有接口可能刷新汇率缓存 |
| `investment set --id` | `PATCH /api/assets` | 独立设置定投策略与金额，无需附带资产市值 |
| `income get/update` | `GET /api/income` 与新增 `PATCH /api/income` | 部分更新工资、月储蓄和年终奖；现有 PUT 保持兼容 |
| `retirement get/update` | `GET/PUT /api/retirement` | 查询退休规划或设置总目标；存在目标明细时拒绝无效的总额修改，明确说明明细决定总目标 |
| `retirement items list/create/update` | 复用退休查询、新增及补充明细修改接口 | 管理目标明细 |
| `valuations refresh` | 新增 `POST /api/valuations/refresh` | 显式刷新行情估值并记录当日快照，返回逐项成功和失败信息 |

归档引入数据库迁移，并同步所有当前资产汇总、估值刷新、历史快照与退休计算的资产过滤规则。已有历史快照保持原值。第一版不向 CLI 开放永久删除。

## HTTP 客户端与认证

- API 地址通过 `--base-url` 或 `FULIBU_BASE_URL` 配置，默认 `http://localhost:3000`，与当前 Docker 网页入口一致。
- 使用绑定用户的可撤销 Bearer Token，支持读权限与写权限；后端继续支持网页 Cookie。
- 新增令牌创建、列举及撤销接口，令牌创建和管理仅接受已登录的网页会话。CLI 登录通过现有登录接口获得会话，再调用令牌创建接口，之后丢弃临时会话。
- 登录交互隐藏密码输入；非交互场景通过环境变量或受限配置文件提供已有令牌。配置文件权限为 0600，日志和错误输出不得打印凭据。
- 首次签发令牌只返回一次明文，数据库保存令牌摘要。用户身份从令牌确定，不接受 CLI 自行指定用户 ID。
- 不自动重试写请求；读请求设置超时，并仅对暂时性连接失败做有界重试。

## CLI 输入输出

- `--json` 输出机器可读的结果；成功输出在 stdout，诊断在 stderr，错误通过退出码和 JSON 错误码识别。
- 金额参数为十进制主货币单位，例如 `--amount 50000 --currency CNY`。客户端按明确字段契约传输，后端内部继续使用分；JSON 金额采用明确的单位字段或带单位字段名。
- 日期使用 YYYY-MM-DD，业务日期按 Asia/Shanghai 解释。区分行情日期、汇率日期和响应时间。
- 修改只传入指定字段，支持 `--dry-run`。后端校验并返回预览，不更新业务数据；实际执行返回修改前后数据。
- 写接口增加操作日志。新增请求使用请求编号与后端幂等记录：同一用户、接口、编号和内容的重试复用原结果，编号相同但内容不同返回冲突。
- 资产和规划修改加入版本检查。CLI 先获取当前版本，再提交指定字段；期间被其他操作修改时返回冲突，不自动覆盖。
- 请求编号、版本与预览校验由后端执行，不能仅依赖 Skill 或 CLI。

## Skill 约定

- 通过 `fulibu … --json` 查询及修改资产星图，不直接操作数据库。
- 修改已有记录时先查询确定资产 ID；重名资产需要消除歧义。
- 使用明确的金额、币种、数量和定投周期；缺少关键参数时请求补充，不能猜测。
- 用户明确授权的修改可直接执行，不增加每次写入都确认的流程。用户只要求比较或预览时使用 dry-run。
- 明确区分资产总额变化与真实投资收益，定投计划与实际扣款，以及行情历史收益与预测收益假设。
- 响应中存在部分失败、过期数据或快照失败时如实报告；写请求超时后核查结果，不盲目重新新增。

## 验证

后端覆盖令牌权限与用户隔离、部分修改、归档对各项汇总的影响、幂等冲突、版本冲突及预览不写入。CLI 使用测试 HTTP 服务验证方法、路径、参数、认证、超时、JSON 与退出码，不接触真实用户数据。

最后以临时 SQLite 和真实后端执行 CLI 查询、新增、修改及归档流程；验证数据经 HTTP 往返，现有 Cookie 网页接口保持兼容。检查 CLI 依赖不含数据库模块。Skill 通过结构校验，并确认命令示例与实际帮助一致。

## 实施顺序

1. 认证、部分更新和读写契约。
2. Go CLI 查询及写入命令。
3. 幂等、版本、操作日志、归档及显式估值刷新。
4. Skill、构建安装说明与端到端验证。
