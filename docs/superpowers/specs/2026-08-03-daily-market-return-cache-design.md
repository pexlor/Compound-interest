# 每日市场收益缓存设计

## 背景与目标

当前股票、基金和货币基金的历史收益由浏览器逐项请求 `/api/market` 计算，再把单个区间的年化收益写回 `assets.annual_rate`。内存缓存只有 10 分钟有效期，服务重启后也会丢失，因此用户切换历史区间或手动同步时需要重复访问行情上游。

本次改造需要实现：

- 每天北京时间 04:10 为数据库中已有的市场类资产预计算近 1、3、5、10 年收益。
- 服务启动后在后台执行一次相同的预热，不阻塞页面读取。
- 用户读取时优先返回当天的持久化缓存；若当天数据缺失，则即时计算、保存并返回。
- 当资产上市或成立时间短于请求区间时，继续使用全部可用历史计算，并明确提示「使用 xxx 天的数据计算」。
- 相同类别和代码由不同用户重复持有时，只计算并保存一份共享结果。

## 范围

预计算覆盖 `stock`、`fund` 和 `money` 类别，固定使用 365、1095、1825、3650 天 4 个区间。

股票、普通基金和 ETF 均需要返回历史不足信息。货币基金继续按最近 7 个数据点的每万份收益折算年化，不展示 n 年历史不足提示，但仍按 4 个区间缓存，以保持读取接口一致并避免重复访问上游。

存款、公积金和固定资产不进入市场收益缓存。汇率缓存和资产历史快照不在本次改造范围内。

## 数据模型

新增 `market_returns` 表：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 自增主键 |
| `category` | text | `stock`、`fund` 或 `money` |
| `code` | text | 规范化后的资产代码，英文代码使用大写 |
| `lookback_days` | integer | 365、1095、1825 或 3650 |
| `calculation_date` | text | 北京时区的计算日期，格式为 `YYYY-MM-DD` |
| `annual_rate` | real | 年化收益率百分比 |
| `period_return` | real | 实际区间收益率百分比 |
| `requested_days` | integer | 请求的历史天数，与 `lookback_days` 一致 |
| `actual_days` | integer | 实际起止日期之间的自然日数 |
| `history_limited` | integer | 是否因上市或成立时间不足而回退到最早数据 |
| `start_date` | text | 实际使用的起始行情日期 |
| `end_date` | text | 实际使用的结束行情日期 |
| `source` | text | 行情和汇率来源说明 |
| `calculated_at` | text | 实际完成计算的时间 |

表上建立 `(category, code, lookback_days, calculation_date)` 唯一索引。写入使用 upsert，使 Cron、启动预热和用户读取并发发生时仍保持幂等。

保留 `assets.annual_rate`，继续用于手动利率资产和市场行情暂不可用时的最后回退值。市场类资产在页面展示和预测时，以当前所选区间的 `market_returns` 数据为准。

## 计算服务

把现有 `app/api/market/handler.ts` 内的行情计算提取为可复用服务。服务输入为 `category`、规范化 `code` 和 `lookbackDays`，输出包含现有收益字段以及 `requestedDays`、`actualDays` 和 `historyLimited`。

历史不足按数据选择过程判定，而不是简单比较 `actualDays < requestedDays`。正常周末、节假日会使目标交易日偏移，不应产生提示；只有目标日期没有可用数据，并最终回退到资产上市或成立以来的最早数据时，才设置 `historyLimited = true`。`actualDays` 使用起止行情日期之间的完整自然日数。

美股收益继续使用起止日期对应的 USD/CNY 历史汇率换算为人民币口径。任一必要的历史汇率缺失时，本次计算失败，不退回美元口径。

## 调度与启动预热

Worker 增加 `scheduled` 入口，Cron 表达式使用 UTC `10 20 * * *`，对应北京时间次日 04:10。任务开始时根据 `Asia/Shanghai` 计算 `calculation_date`，不能依赖运行环境默认时区。

批量任务从 `assets` 查询不重复的 `category + code`，再为每项计算 4 个历史区间。任务采用有限并发，复用现有的上游请求并发限制。单项失败只记录日志并继续处理其他项，成功结果立即写入数据库。

Cloudflare Worker 没有传统服务器进程的可靠启动回调。每个新 Worker 实例首次收到普通请求时，使用模块级 Promise 防重，并通过 `ctx.waitUntil` 在后台触发一次批量预热；请求本身不等待预热完成。本地启动脚本的健康检查会触发首次请求。数据库唯一索引和 upsert 负责跨实例幂等。

## 用户读取流程

新增当前用户的批量收益读取能力，接收一个受支持的 `lookbackDays`：

1. 鉴权并读取当前用户持有的市场类资产。
2. 按 `category + code` 去重。
3. 批量查询北京时间当天的缓存。
4. 对缺失项调用计算服务，并在成功后写入当天缓存。
5. 返回每个资产代码对应的收益结果。
6. 如果即时计算失败，返回该键最近一次成功缓存并标记 `stale: true`。
7. 如果从未有成功缓存，则返回该项错误；前端保留 `assets.annual_rate`，其他资产仍正常展示。

现有单代码 `/api/market` 能力保留，供新增资产时读取一个代码，也改为相同的持久化 read-through 流程。并发读取相同键时继续通过进程内 in-flight Promise 合并请求，数据库唯一约束处理跨实例并发。

## 前端行为

登录后读取资产时，同时批量读取默认近 3 年的收益缓存。用户切换近 1、3、5、10 年历史区间时，自动执行一次批量读取并更新所有市场类资产的 `annual_rate`，不再逐项发起请求。

原「读取最新收益率」按钮保留，语义改为重新读取当天缓存并补齐缺失项，不强制覆盖当天已经成功的结果。

当 `historyLimited` 为真时：

- 资产列表的年化收益旁显示「历史不足，使用 xxx 天的数据计算」。
- 资产详情展示请求区间、实际起止日期和实际天数。
- 组合预期年化区域提示其中包含历史不足的资产，但这些收益仍参与组合计算。

旧缓存回退时显示数据日期和旧数据状态。单项没有任何可用结果时保留资产表中的上次收益率，并提示该项行情暂不可用，不阻断整个组合页面。

## 错误处理与可观测性

- 定时任务和启动预热输出批次开始、结束、成功数、失败数及失败键，不记录用户身份或敏感数据。
- 缓存读取输出统一的 `[market-return]` 前缀和结构化字段，区分 `cache_hit`、`cache_miss`、`calculate_success`、`stale_fallback` 和 `calculate_failed`，便于本地调试请求耗时与回退路径。
- 调试日志包含类别、代码、历史区间、缓存日期、实际数据天数和耗时；不输出用户 ID、Cookie 或上游响应正文。
- 不因一个代码或一个区间失败而取消其他计算。
- 非法类别、代码或区间在进入上游请求前拒绝。
- 只有完整且数值有效的结果才能写入缓存。
- 当天缓存一经成功写入，普通读取不主动刷新，以保证同一天结果稳定并控制上游调用量。

## 测试策略

采用测试驱动开发，至少覆盖以下行为：

- `market_returns` 的 upsert 和唯一键语义。
- 当天缓存命中时不访问行情上游。
- 当天缓存缺失时计算、落库并返回。
- 即时计算失败时回退最近一次缓存，并正确标记 `stale`。
- 从未成功计算时返回单项错误，不影响批量中的其他项。
- 多用户或同一用户的重复代码只计算一次。
- 批量预热固定处理 365、1095、1825、3650 天。
- 批量任务隔离单项失败，并遵守并发限制。
- UTC 时间正确映射为 `Asia/Shanghai` 的 `calculation_date`。
- Worker Cron 配置对应北京时间 04:10。
- 正常休市偏移不标记历史不足；回退最早行情时返回 `historyLimited` 和准确 `actualDays`。
- 股票、普通基金和 ETF 展示历史不足提示；货币基金不展示。
- 切换历史区间只发起一次批量读取，并更新组合计算使用的收益率。

## 验收标准

- 数据库已有市场类资产在每天北京时间 04:10 后具备当天 4 个区间的缓存，失败项除外。
- 服务首次收到请求时后台触发一次预热，且不增加该请求的响应等待时间。
- 用户读取已有当天缓存时不访问外部行情服务。
- 用户读取缺失的当天数据时自动补算并持久化。
- 历史不足的股票、普通基金和 ETF 明确显示实际计算天数。
- 上游部分失败不会导致整批任务或整个资产页面失败。
