# 资产历史走势设计规格

## 目标

为每个用户保存每日最后一次人民币总资产快照，并在 Dashboard 展示历史总资产折线图和明细表。

历史总额使用快照写入时的汇率计算。之后汇率变化不会改写已经保存的历史记录。

## 触发规则

以下操作成功后更新当前用户当天快照：

- 新增资产
- 修改资产金额或币种
- 删除资产
- 手动刷新汇率并成功取得新汇率

以下操作不更新快照：

- 修改资产年化收益率
- 读取行情
- 读取历史记录

同一用户同一天只保留一条记录，后一次触发覆盖前一次记录。

## 数据模型

新增 `exchange_rates` 表：

- `currency`：主键，币种代码
- `cny_rate`：1 单位外币对应人民币金额，CNY 为 1
- `rate_date`：上游汇率日期
- `updated_at`：本地写入时间

新增 `asset_history` 表：

- `id`：自增主键
- `user_id`：关联用户并级联删除
- `snapshot_date`：业务日期，使用 Asia/Shanghai
- `total_cny`：人民币分，整数
- `trigger`：`asset_change` 或 `exchange_refresh`
- `rate_date`：计算时使用的汇率日期，可为空
- `created_at`、`updated_at`

唯一约束为 `(user_id, snapshot_date)`。所有查询必须限定当前用户。

## 服务端流程

1. 汇率 API 成功取得数据后，写入 `exchange_rates`，再为当前用户计算当天快照。
2. 资产 API 完成新增、金额/币种修改或删除后，读取数据库内最近汇率并计算当天快照。
3. 计算时如果某项外币资产没有可用汇率，不写入部分总额；资产本身的变更仍保持成功，并返回快照未记录状态。
4. 快照计算以资产金额分乘汇率后四舍五入到人民币分。
5. 快照写入使用 UPSERT，确保同日最后一次触发覆盖旧值。
6. 新增 `GET /api/history`，返回当前用户按日期升序排列的历史记录，并限制合理最大条数。

## 前端展示

新增“资产历史”区域：

- 折线图展示日期和人民币总资产。
- 明细表展示日期、总资产、较上一条的变化金额和变化百分比。
- 少于两条记录时显示空状态，不绘制误导性的趋势。
- 移动端表格允许横向滚动，图表使用稳定高度。
- 资产变更或汇率刷新成功后重新读取历史数据。
- 快照未记录时用提示说明原因，不阻塞原有资产操作。

## 测试范围

- 注册用户只能读取自己的历史记录。
- 新增、金额/币种修改、删除会写入快照。
- 年化收益率修改不会写入快照。
- 手动刷新汇率会写入快照并保存汇率。
- 同一天多次触发只保留最后一次总额。
- 缺失汇率不会写入部分总额。
- 历史 API 返回升序数据，变化金额和百分比计算正确。
- Dashboard 展示走势图、明细表和空状态。
